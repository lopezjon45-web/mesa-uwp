# One S harness

The `one-s` workflow (`.github/workflows/one-s.yml`) runs on every push to `one-s-dxbc`. It builds the UWP DLLs and gates them on the Jaguar instruction set (artifact `mesa-uwp-one-s`). It also builds the same tree for desktop Windows and runs every glprobe scene (`one-s/glprobe/`) on the runner's WARP adapter twice, each scene in its own process: first on the normal DXIL path, where every scene must match its reference in `one-s/glprobe/ref/` within 3 per channel, then with `D3D12_MAX_SHADER_MODEL=51`, which caps the d3d12 driver at shader model 5.1 as the One S does. The capped run fails the job only for scenes listed in `one-s/glprobe/expected-dxbc-pass.txt`; it prints the per-scene table and uploads images, diffs and logs (artifact `glprobe-results`) either way. To run it locally on Windows, build glprobe with `one-s\glprobe\build.cmd <mesa>\include`, put Mesa's `opengl32.dll`, `libgallium_wgl.dll` and the SDK's `dxil.dll` beside it, and run `python one-s/glprobe/run.py --exe glprobe.exe --out results --expect one-s/glprobe/expected-dxbc-pass.txt` with `GALLIUM_DRIVER=d3d12`. To add a scene to the ratchet, add its name on its own line in `expected-dxbc-pass.txt` once the capped run shows it passing; from then on any change that breaks it fails CI. A new scene needs a reference: run the workflow by hand with `write_refs` checked, check the new image from the `glprobe-results` artifact (`new-ref/`) by eye, and commit it under `one-s/glprobe/ref/`.
